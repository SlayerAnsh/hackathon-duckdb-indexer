**Goal:** Users own their widgets on Arkiv. The app wallet still creates every widget (so `$creator` keeps proving provenance) but creates it readonly and permissionlessly extendable and hands ownership to the user's Privy wallet in the same batch. Users extend, delete and transfer by signing in the browser; editing saves a new version; dashboards, links and official items stay app owned.

**Architecture:** Server create path gains creation flags, an ownership change and an optional `replaces` relink; the three widget write endpoints are removed. Official status requires app ownership. Reads already select `owner` (`DASH_SELECT` in `entities.ts`); DuckDB gains an `owner` column in the `dash` CTE. Browser signing runs inside the lazily loaded `PrivyBridge` in a new `sign` mode that builds an SDK wallet client over a split transport (wallet methods to the Privy EIP 1193 provider, reads to the Tiramisu RPC). Pure helpers carry all decisions so tests stay offline.

**Tech Stack:** Next.js 16, React 19, `@arkiv-network/sdk` 0.8.1, viem 2.57.7, `@privy-io/react-auth` 3.50.0, Bun test with `renderToStaticMarkup`.

## Review Focus

1. Trust boundary on create: a user widget is created by the wallet with `flags: { readonly: true, permissionlessExtension: true }` and its `ownershipChanges` entry targets exactly the session address and exactly the predicted widget key; links never carry flags and are never transferred. Pinned in Task 3.
2. `replaces` authorization: the server checks the old widget's Arkiv `owner` (not `user`) equals the session address, repoints only links whose `user` is the session address, and sends nothing when the check fails. Pinned in Task 3.
3. Official marker: `user == wallet` AND `owner == wallet` in entities, RPC expressions, DuckDB and keepalive; a user owned entity is never official and never extended by keepalive. A user can transfer a readonly widget to the app wallet, but its `user` attribute cannot change, so it never becomes official. Pinned in Task 1.
4. Ownership checks in the UI use `owner`, never `user` (owner view, Delete, Transfer, "My widgets"). Pinned in Tasks 1 and 4.
5. Wallet error mapping: rejection is silent, `NotOwner`, `EntityExpired`, insufficient funds and cap are recognised through nested `cause` chains, and no raw provider message reaches the UI. Pinned in Task 2.
6. Balance threshold arithmetic in wei (bigint, no floats), zero disables signing, low warns and allows, unknown hides the warning. Pinned in Task 2.
7. Pending writes for direct transactions use the head read before sending as `afterBlock` and clear through the existing `useSynced`. Pinned in Tasks 3 and 4.
